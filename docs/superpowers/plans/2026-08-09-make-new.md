# `make new` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a `make new TITLE="…" CATEGORY=… [DATE=…]` target that writes a post stub into `posts/` and cannot emit a filename any of grampa's five parse-time checks would reject.

**Architecture:** One `.PHONY: new` rule whose recipe is a single `; \`-continued shell line, in the style of `setup`'s. Two new `:=` variables hold `tr` sets *derived from `$(BAD_CHARS)`* rather than retyped, and one holds the slug pipeline itself so title and category share it. `DATE=` gets a pure-make shape check that runs before `date_select` is ever expanded. `new` joins `NONBUILD_GOALS`.

**Tech Stack:** GNU make 4.2+, bash, `tr`, `sed`, `date`, `cat`. No new dependencies — nothing here is outside what the Makefile already uses.

**Spec:** `docs/superpowers/specs/2026-08-09-make-new-design.md`. Read it before starting. Everything below implements it; where this plan and the spec disagree, the spec is wrong and should be corrected.

## Global Constraints

- **The Makefile is the program.** No new scripts, no new languages, no new dependencies. `tools/` is for one-off maintenance and this is not one.
- **Tabs in the Makefile.** Recipes prefixed with `@`, each echoing a short human-readable line.
- **`#`-banner comment blocks above every new rule and helper**, in the existing style. This repo's comments carry the *why*, including what was tried and failed. Write them that way.
- **Every claim in a comment must be one you ran.** `docs/backlog.md` item 14 tracks confident-but-false claims in this repo; the count is at eighteen. Do not add the nineteenth.
- **`SHELL := /bin/bash` is set unconditionally**, so bashisms are safe and `/bin/sh` never enters it.
- **Tests are plain bash in `tests/run.sh`**, one sandbox per test, registered by name in the flat list at the end of the file (from line ~3776).
- **After each task, dispatch a Fable review of that task's diff before starting the next**, per CLAUDE.md's "Review cycle". Four checkpoints, no exceptions.
- **Run the suite from the repo root with `make test`.** From a scratch copy you must also copy `tools/`, or you get ~15 unrelated failures on Linux.

- [ ] **Step 4: Add the rule**

Above `.PHONY: setup` in `Makefile`:

```make
#
# make new TITLE="Installing a doorbell" CATEGORY=home
# make new TITLE="Old news" CATEGORY=home DATE=2026-07-04
#
# Writes posts/<date>-<category>_<slug>.txt, prints the
# path, and stops. It does not build and it does not open
# an editor: a make recipe that seizes the terminal behaves
# differently under -j, in a pipe, and over ssh.
#
# The point is an invariant, not convenience. There are five
# parse-time errors a hand-typed filename can trip, and this
# target must be incapable of emitting a name that trips any
# of them -- its output set is a subset of the grammar's
# accepted set. Every refusal below holds that line, and
# each one happens BEFORE anything is written, so a refused
# new leaves posts/ byte-identical.
#
# TITLE and CATEGORY are read from the ENVIRONMENT, not
# interpolated into the recipe text. Make exports
# command-line variables to recipe shells, so "$$TITLE"
# reads a title containing " ' $ ` & with nothing executed
# and nothing quoted wrong -- the same discipline BLOG_NAME
# and SITE_URL use to reach awk through ENVIRON[]. Verified
# with a title carrying all five.
#
# posts is the only prerequisite: its mkdir -p is what makes
# this work on a tree that has never built. config is not
# needed -- no config key is read here.
#
.PHONY: new
new: posts
	@if [ -z "$$TITLE" ]; then \
		echo "grampa: new: TITLE= is required" >&2; exit 1; fi; \
	if [ -z "$$CATEGORY" ]; then \
		echo "grampa: new: CATEGORY= is required" >&2; exit 1; fi; \
	echo "Created posts/PLACEHOLDER"
```

The `PLACEHOLDER` line is replaced in Task 2. It exists so this task's tests are honest about what is built so far.

```make
#
# The two tr sets make new slugifies with, derived from
# BAD_CHARS rather than retyped. A second, independently
# written copy of that list is the drift date_select is
# factored to avoid: a generator that strips a different set
# than the checker rejects is the same class of defect as no
# generator at all.
#
# SLUG_DELETE is the two quote characters, written as tr's
# own octal escapes because no single shell quoting handles
# both at once. They are DELETED rather than translated, so
# "Tom's doorbell" becomes toms-doorbell and not
# tom-s-doorbell.
#
# SLUG_XLAT is everything else in BAD_CHARS, plus the _ that
# separates category from slug and which new writes itself.
# The backslash is DOUBLED, and that is not decoration: a
# literal \ in a tr set is an escape introducer, so the
# undoubled set spends it escaping the ] beside it and
# leaves a backslash in the title untranslated. Verified --
# a\b^c]d came through as a\b c d before the doubling and
# a-b-c-d after.
#
SLUG_DELETE := \047\042
SLUG_XLAT := $(subst \,\\,$(subst $(space),,$(filter-out ' ",$(BAD_CHARS))))_

#
# The slug pipeline, as one shell fragment, used twice --
# once for the title and once for the category. Written as a
# variable rather than twice in the recipe for the same
# reason the tr sets are derived: two copies drift.
#
# Every stage is LC_ALL=C, which is what makes it UTF-8
# safe. A multi-byte character's continuation bytes are all
# >= 0x80 and can never collide with the ASCII punctuation
# being stripped, so café and 日記 survive into filenames
# the grammar already accepts. The lowercase stage is
# A-Z only for the same reason: a bytewise tr cannot
# case-fold É, so it leaves it alone rather than mangling
# it.
#
# The [:cntrl:] stage is FIRST, and it is a separate stage
# rather than a BAD_CHARS clause -- mirroring the split
# between bad_chars_in above and CONTROL_CHAR_NAMES below,
# and for the same reason: a control byte cannot be an
# element of a make list. Without it the invariant is simply
# false. Control bytes are not in BAD_CHARS, nothing else
# here touches them, and a lone tab is not an empty slug, so
# a tab in a title wrote posts/...home_a<TAB>b.txt at exit
# 0 and a NEWLINE wrote a name that breaks every LATER
# build: ls prints it as two lines, the grep drops one, and
# the check dies naming posts/lines.txt, a file that does
# not exist. The generator built the one name its own
# successor cannot survive. Reproduced end to end.
#
# Translated to a space rather than deleted, so a pasted
# two-line title becomes two-lines and not twolines.
#
# tr's set2 is written '[ *]' and not ' ': GNU tr pads a
# short set2 with its last character, POSIX leaves that to
# the implementation, and this project treats macOS as
# first-class. Verified on GNU; the BSD leg is the standing
# item for the branch review.
#
SLUGIFY := LC_ALL=C tr '[:cntrl:]' '[ *]' \
	| LC_ALL=C tr -d '$(SLUG_DELETE)' \
	| LC_ALL=C tr '$(SLUG_XLAT)' '[ *]' \
	| LC_ALL=C tr 'A-Z' 'a-z' \
	| LC_ALL=C tr -s ' ' \
	| sed 's/^ *//; s/ *$$//' \
	| LC_ALL=C tr ' ' '-'

#
# The title as it goes into the front matter: kept verbatim
# except that control characters become spaces.
#
# That exception is load-bearing rather than tidy. The front
# matter is ONE LINE -- printf 'title: %s\n' -- so a newline
# in the title splits it in two, and PARSE_FRONT_MATTER
# reads the second line as something it is not. Squeezing
# runs of spaces afterwards keeps a pasted multi-line title
# from becoming a line of gaps.
#
SANITIZE_TITLE := LC_ALL=C tr '[:cntrl:]' '[ *]' \
	| LC_ALL=C tr -s ' ' \
	| sed 's/^ *//; s/ *$$//'
```

- [ ] **Step 1: Write the failing tests**

```bash
#
# The blocking finding of the spec review. Control bytes
# are not in BAD_CHARS and nothing else in the pipeline
# touches them, so before the [:cntrl:] stage a tab wrote a
# filename the build rejects -- and a newline wrote one that
# breaks every LATER make in the directory, which is why the
# second half of this test builds afterwards rather than
# only checking the filename.
#
test_new_strips_control_characters() {
	sandbox new_control_chars
	build new TITLE="$(printf 'Two\nlines')" CATEGORY=home DATE=2026-01-02 || return
	assert_file posts/2026-01-02-home_two-lines.txt
	build new TITLE="$(printf 'a\tb')" CATEGORY=home DATE=2026-01-03 || return
	assert_file posts/2026-01-03-home_a-b.txt
	build || return
	assert_file build/2026/01/02/two-lines.html
	assert_file build/2026/01/03/a-b.html
}

#
# The front matter is one line, so a newline in the title
# has to be flattened there too -- not only in the slug.
# Without it PARSE_FRONT_MATTER reads the tail of the title
# as something it is not.
#
test_new_keeps_the_front_matter_on_one_line() {
	sandbox new_one_line_front_matter
	build new TITLE="$(printf 'Two\nlines')" CATEGORY=home DATE=2026-01-02 || return
	assert_grep posts/2026-01-02-home_two-lines.txt "title: Two lines"
	assert_eq "front matter line count" "1" "$(grep -c '^title: ' posts/2026-01-02-home_two-lines.txt)"
	build || return
	assert_grep build/2026/01/02/two-lines.html "<h4>Two lines</h4>"
}

#
# An empty title slug publishes build/<y>/<m>/<d>/.html and
# is rejected by check_post_name; an empty category is
# rejected by its sibling clause. Neither can reach the
# build, because new refuses first -- and refuses without
# writing.
#
test_new_refuses_a_title_with_no_usable_characters() {
	sandbox new_empty_title_slug
	build_expect_fail new TITLE="!!!" CATEGORY=home || return
	assert_out_grep "no usable characters"

}
```

```make
# classes, so the enumeration is the check -- the same shape
# BAD_CHARS uses further down, and closed the same way.

strip_digits = $(subst 0,,$(subst 1,,$(subst 2,,$(subst 3,,$(subst 4,,$(subst 5,,$(subst 6,,$(subst 7,,$(subst 8,,$(subst 9,,$(1)))))))))))

# Empty when $(1) is three hyphen-separated runs of digits,
# non-empty otherwise. make new checks DATE= with this
# BEFORE date_select is expanded, and that order is the
# whole point rather than tidiness.
#
# date_select interpolates its argument into RECIPE TEXT --
# it is the one date site whose input is not a filename that
# has already been through the character check. Under the

# in DATE escapes it. Verified: DATE='x";touch PWNED;"'
# created PWNED.
#
# $(if) expands only the branch it takes, which is what
# makes this a fix and not a warning: a bad shape means the
# branch containing date_select is never expanded, so the
# payload never becomes recipe text at all.
#
# It accepts an unpadded 2026-7-4, because the grammar does.
# A generator that refused a name the build accepts would be
# wrong in the other direction.
#
date_shape_bad = $(if $(filter 3,$(words $(subst -,$(space),$(1)))),$(subst -,,$(call strip_digits,$(1))),$(1))
```

```markdown
**`make new` writes a filename none of these rules can reject**, which is the whole reason it
exists. `make new TITLE="Installing a doorbell" CATEGORY=home` writes
`posts/<today>-home_installing-a-doorbell.txt` — a `title:` line and the delimiter `cat`ted
from `.source/splitter.txt`, nothing else — prints the path, and stops. `DATE=` backdates.
`TITLE` and `CATEGORY` are required; there is no default category and no `SLUG=` override.

Slugification is bytewise under `LC_ALL=C`: control characters and every `BAD_CHARS` member
plus `_` become spaces (`'` and `"` are deleted instead, so `Tom's` is `toms`), `A-Z` is
lowercased, runs of spaces collapse, and spaces become hyphens. The `tr` sets are derived from
`$(BAD_CHARS)` rather than retyped, so the generator strips exactly what the checker rejects.
Non-ASCII survives — `Café notes` becomes `café-notes` and `日記` stays — because the grammar
accepts it. So does `.`, so `Version 2.0 notes` keeps its dot.

It refuses, before writing anything, on: a missing `TITLE` or `CATEGORY`, a title or category
that slugifies to nothing (`!!!`), an existing file at that path, a post in another category
that already builds the same permalink, and a `DATE` that is not three runs of digits or not a
real calendar date.

Four things to know:

- **A pre-existing malformed post blocks it.** `make new` parses the whole Makefile, so a bad
  filename already in `posts/` kills the invocation before it can write a good one. The tool
  that prevents bad names cannot run in a directory that already has one.
- **`$(…)` in `TITLE` is expanded by make before the recipe runs.** `make new
  TITLE='$(shell echo PWNED)'` prints `PWNED` and titles the post `x`. Command-line variables
  are expanded when make exports them, so no quoting in the recipe can help; it is the same
  trust level as `markdown=` in `config`. A literal `$(` in a title is typed by hand.
- **`DATE` is the one input that reaches the shell as recipe text.** `date_select`
  interpolates it, so unlike `TITLE` — which is read from the environment as `$$TITLE` and is
  safe with `"`, `'`, `$`, `` ` `` and `&` — it needs the `date_shape_bad` check, which runs
  in the `$(if)` branch that decides whether `date_select` is expanded at all. Before it, a
  `DATE` of `x";touch PWNED;"` created `PWNED`.
- **An unconfigured tree is asymmetric, and correctly so.** The default date is
  `date +%Y-%m-%d` and expands no date helper, so `make new` works with no `config.mk`;
  `DATE=` goes through `date_select` and says ``run `make setup` first``.

Some legal slugs are ugly and stay legal: `TITLE='.'` builds `..html`, a leading or trailing
hyphen survives, `'- - -'` gives `-----.html`. All five checks accept them.
```
